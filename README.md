# boomPI

boomPI 是面向 RV1106 自研板的嵌入式语音 AI 项目，目标是在现有双麦克风和扬声器硬件上实现可持续对话的“小智 AI”形态。

## 当前需求

- 双麦克风采集与扬声器播放。
- 使用播放参考信号进行声学回声消除（AEC），避免设备听到自己的声音。
- 接入 Qwen 系列服务完成 ASR、对话模型和 TTS；具体模型、协议与部署方式待确认。
- 使用多线程组织音频采集、回声消除、网络通信、对话状态和音频播放。
- 在 RV1106 Linux/Buildroot 环境运行，并提供可重复的交叉编译、部署和板端验证流程。

## 暂定技术栈

- C++ 与 CMake。
- Linux、RV1106、ALSA。
- Qwen ASR / LLM / TTS API（型号待选）。
- 自适应滤波与残余回声抑制（具体 AEC 实现待评估）。
- Git 与 GitHub。

## 初步模块边界

- `audio`：双麦采集、播放参考、扬声器输出和音频缓冲。
- `aec`：延时对齐、回声路径估计、双讲检测和残余回声抑制。
- `speech`：ASR 与 TTS 服务接口。
- `dialog`：Qwen 对话请求、上下文和会话状态机。
- `transport`：HTTP/WebSocket、鉴权、超时、重试和断线重连。
- `app`：线程生命周期、事件编排、打断和整机状态管理。
- `platform`：RV1106/ALSA/系统服务适配。

最终目录、线程模型、音频格式、协议和依赖将在需求访谈后确定。

## 开发计划

1. 明确产品交互、Qwen 模型/API、网络条件和性能指标。
2. 确定音频链路、AEC 方案、线程/队列模型及资源预算。
3. 编写项目级 `AGENTS.md`，固化架构边界、编码规范和验收标准。
4. 建立 CMake 工程、交叉编译工具链和最小板端 smoke test。
5. 分阶段实现音频、AEC、ASR、对话、TTS 与打断能力。
6. 在真实双麦和扬声器环境下测试延时、回声抑制、稳定性与断网恢复。

## 当前状态

项目处于需求和架构设计阶段，尚未开始业务代码开发。API 密钥等敏感配置不会提交到仓库。

## 测试链路与结果

1. 板端使用直接 ALSA 录制 8 秒 `48 kHz / S16_LE / 2ch` 原始音频，退出码为 0，
   字节数为 1,536,000，与请求时长和格式完全一致。
2. 左声道存在明显直流偏置：均值约 `+0.196`，范围约 `+0.132..+0.287`；右声道为
   恒定 `-1.0` 满量程。该结果不能记作双麦正常。
3. 为了只验证端到端真人交互，临时只取左声道，执行 80 Hz 高通、归一化并降采样为
   `16 kHz / S16_LE / mono`，得到 256,000 字节输入。处理后均值约为 0，RMS 约为 0.043。
4. Windows 主机通过中国北京区 Qwen Realtime 上传该真人录音，1.63 秒内收到 69 字节
   文本事件和 172,800 字节 `24 kHz / S16_LE / mono` 音频事件；测试通过。
5. 返回音频转换为 `48 kHz / S16_LE / 2ch`，数字增益提高 12 dB 后通过 `hw:0,0`
   播放，`aplay` 退出码为 0。用户现场确认听到回答且声音清楚。

## 判定边界

- 通过：真人说话 -> 板载麦克风 -> 主机 -> Qwen 中国北京区 -> TTS -> 板载喇叭。
- 通过：当前临时预处理后的单路语音可被 Qwen 接收并生成清楚的语音回答。
- 未通过：双麦通道健康、产品态实时采集、AEC、VAD、唤醒、打断、连续对话和网络恢复。
- 严重问题：右声道恒定负满量程；左声道有明显直流偏置。进入产品音频运行时前必须检查
  ADC mode、ALSA slot 布局、Codec mixer/驱动配置与模拟链路，不能用本次单路临时处理掩盖。

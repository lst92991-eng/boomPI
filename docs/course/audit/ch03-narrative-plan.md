# 第3章《操作系统简介》连续叙事基线

## 1. 本章定位与唯一主线

第3章建议保留 **5个二级标题**。它不是Linux命令速查表，也不是内核原理课，而是回答第2章结尾留下的问题：原理图已经把处理器、内存、存储和外设接好，应用程序为什么仍不能直接使用它们？

全章只沿一条因果链推进：

> 硬件连接只提供物理条件 → 操作系统统一安排处理器、内存和外设 → 正在运行的程序以进程和线程的形式获得资源 → 内存、中断和文件系统托住运行过程 → 启动程序把内核和根文件系统带起来，应用才真正出现。

章首不写“本章目标”或课程路线，直接承接第2章：

> 上一章已经把供电、存储、网口、摄像头和屏幕的连接讲清楚。把这些器件接到RV1106G3，只说明硬件具备工作条件；应用程序仍然不知道什么时候可以使用处理器、数据应放到哪块内存，也不能各自抢占网口和摄像头。负责安排这些资源的软件，就是操作系统。

紧接着统一用词，防止后文把“Linux”和“内核”混成一件事：

> 在这本课程里，“Linux内核”专指负责管理处理器、内存和设备的核心部分；“Linux系统”则包括内核以及应用运行所需的库、配置和文件。引导程序位于Linux之前，负责把内核带到可以运行的位置。

章末只把问题交给第4章，不提前列命令：

> 系统完成启动以后，内核已经在管理硬件，根文件系统也已经可用。下一章再从电脑登录boomPI，用真实终端观察目录、进程和存储空间；本章不提前展开命令格式。

- 程序、进程、线程和并发的最小区别。

## 4. 建议的5个二级标题与段落节奏

### 3.1 硬件已经接好，为什么还需要操作系统

本节不要从百科定义起笔。先写“应用直接控制硬件会遇到什么”，再给操作系统名称。

可直接使用的自然段节奏：

1. **承接硬件**：原理图能确认处理器与eMMC、网口、摄像头、屏幕之间有电气连接，却不能决定多个程序怎样轮流使用处理器，也不能防止两个程序同时改写同一块硬件。连接是硬件条件，分配和保护是软件问题。
2. **说明必要性**：功能很单一的微控制器程序可以从头到尾自行管理外设；boomPI同时要处理存储、网络、图像和交互，若每个应用都自行操作寄存器，硬件初始化、冲突处理和错误恢复会散落在每个程序中。操作系统把这些共同工作集中管理。
3. **给正式名称**：操作系统（OS）位于应用和硬件之间。Linux系统最核心的部分叫Linux内核；它决定处理器时间怎样分配、内存怎样使用，并通过驱动管理外设。应用只提出需求，不需要知道每一个引脚和寄存器的细节。
4. **回到本板**：图中只对应第1、2章已经出现的五类资源：Cortex-A7、运行内存、eMMC、网络接口和图像/交互外设。不要加入尚未讲到的云服务、语音算法或项目线程。

建议图片：

- **图3-1 应用、内核与boomPI硬件的关系**。上层只放“应用A、应用B”，中间只放“Linux内核”和“驱动”，下层只放“处理器、内存、存储、网络、图像/交互”。箭头表示请求与结果，不画成卡通管家，也不把内核子系统全部塞进图中。
- 图片依据应绑定Linux内核官方文档与第1章RV1106官方框图；图注写“教学关系图”，不能伪装成当前板端实测。

> 操作系统并不是替应用完成所有工作，它先把硬件整理成程序可以请求的资源。下面沿一次“应用想使用外设”的过程，看内核在中间做了什么。

### 3.2 操作系统怎样把硬件交给程序

这一节把“硬件资源管理”落到三个具体问题：谁使用处理器、数据放在哪里、外设由谁控制。不要列内核模块清单。

可直接使用的自然段节奏：

1. **处理器**：Cortex-A7一次只能沿当前指令流继续执行。内核记录哪些工作正在等待，并安排它们在合适的时机获得处理器。正式名称“调度”放在这句之后，不讲时间片长度和策略名称。
2. **内存**：程序开始运行前，代码和数据需要进入运行内存。内核给不同程序安排可用区域，并阻止一个普通程序随意覆盖另一个程序的数据。此处只给“内存分配与保护”，不展开页表、swap和slab。
3. **外设**：应用若要联网、取图或显示，不直接寻找RV1106寄存器，而是向内核提出请求。内核中负责具体硬件的部分叫驱动；应用进入内核服务的统一入口叫系统调用。两个正式词分在相邻两句中，不连续堆定义。
4. **证据边界**：第2章原理图只能证明外设连接；本节关系图只能说明Linux的职责。设备节点、驱动绑定和功能是否可用，要等真实系统启动后再观察。

本节不另加图片。继续使用图3-1，让同一张图完成一次共同观察：图前要求从应用沿箭头找到内核，图后指出应用没有直接连到硬件。避免每个概念各画一张装饰图。

自然过渡：

> 每一种硬件有了统一入口，程序仍不能排队等前一个工作完全结束。网络数据、摄像头画面和界面更新往往在同一段时间内推进，操作系统还要安排这些正在运行的工作。

### 3.3 多个程序为什么能在同一段时间内向前运行

本节先从“文件”和“正在运行”区分程序与进程，再在进程内部引出线程。不要一上来给进程状态图。

可直接使用的自然段节奏：

1. **程序到进程**：存放在eMMC中的应用只是一个程序文件。Linux把它装入内存并开始执行以后，这一次运行才叫进程。一个程序可以先后启动多次，每次运行都有自己的进程身份和资源记录。
2. **进程到线程**：一个进程可以只沿一条执行路线工作，也可以在内部安排多条执行路线。这些路线叫线程；同一进程内的线程共享代码和大部分数据，因此配合方便，也必须避免同时改坏同一份数据。互斥和竞态只留一句边界，第11章再结合源码处理。
3. **并发与调度**：操作系统让多个可运行的进程或线程轮流获得处理器，每次只向前执行一小段。多个工作在同一段时间内交替推进，称为并发；它不要求它们在同一个瞬间都占用处理器。不要再用多人教室、餐厅或多条道路类比。
4. **本板语境**：可以用“系统服务与一个前台应用同时存在”说明需求，不提前宣称当前项目已经建立摄像头线程、网络线程或音频线程。具体线程数量和所有权必须到第11章从源码提取。

建议图片：

- **图3-2 进程与线程的最小关系图**。左侧放“程序文件”，中间放“进程A/进程B”，进程A内部只画两条线程；下方用一条简短时间线表示处理器在A1、B1、A2之间切换。图中不出现优先级、就绪/阻塞状态、上下文寄存器和调度队列。
- 来源标注为基于Linux官方进程/调度文档整理的教学图，不使用FreeRTOS截图证明Linux行为。

自然过渡：

> 调度解决了谁在什么时候运行，但程序要继续工作，还需要地方保存当前数据，并能及时知道外设发生了什么。长期保留的内容又不能只放在运行内存中。

### 3.4 内存、中断和文件系统各管哪一段

三个术语放在同一节，是因为它们分别对应“正在算、事情来了、断电后还要保留”三个连续问题。正文仍按三段展开，不在标题下再拆三级标题。

可直接使用的自然段节奏：

1. **内存承接运行**：程序从存储器读出后，需要放进运行内存才能高效执行；计算中的图像、网络数据和界面状态也暂存在这里。断电后这些内容通常消失，所以运行内存不承担长期保存。内核负责分配和回收，不讲虚拟内存内部结构。
2. **中断承接事件**：外设有新事件时，不必让处理器一直反复询问。网口收到数据、定时器到点或某个设备完成工作，都可以发出信号提醒处理器，这种提醒叫中断。内核与驱动先处理硬件事件，再让等待结果的程序继续；不讲IRQ编号和处理函数层次。
3. **文件系统承接长期内容**：eMMC只提供按位置读写数据的能力，本身不知道哪个数据块属于程序、配置或图片。文件系统给这些数据建立名称、目录和访问规则。Linux把目录组织成一棵从根目录开始的树，但具体目录和命令留到第4章。
4. **收束关系**：内存保存当前运行需要的数据，中断把外设事件及时送到内核，文件系统组织需要长期保留的内容。三者职责不同，却共同支撑一个进程从启动到持续运行。

本节原则上不加第二张“内核大全图”。若正文需要视觉停顿，只允许放一个很小的三栏关系图：`运行中的数据—内存`、`外设发生事件—中断`、`长期内容—文件系统`。它不计作新的架构图，也不要在栏内继续列术语。

自然过渡：

> 这些机制只有在Linux内核真正开始运行以后才存在。板子刚刚上电时，内存中还没有操作系统，下一步要看内核怎样被装入并找到根文件系统。

### 3.5 从上电到应用出现，系统经历了什么

本节按时间顺序写，但不要把启动链拆成五个小标题。每段只推进一步，图中名称与正文第一次出现的顺序一致。

可直接使用的自然段节奏：

1. **找到启动内容**：电源稳定并解除复位后，芯片内部固化的启动代码先寻找可用的启动介质。这里用普通话说明作用，再给BootROM名称；具体从eMMC还是其他介质启动，必须以当前镜像配置和板端证据为准。
2. **把内核带入内存**：随后运行引导程序。它完成启动所需的最少准备，把Linux内核和硬件描述装入内存，再把执行权交给内核。当前课程若使用U-Boot，正文在核对SDK配置或启动日志后再写名称，不能只凭参考文档下结论。
3. **让内核认识板子**：内核启动时需要知道板上有哪些硬件、地址和连接关系。这份硬件说明由设备树提供，启动镜像中通常使用编译后的DTB。这里只说明用途；DTS、DTSI、DTC和节点语法后移。
4. **找到系统文件**：内核初始化处理器、内存和必要驱动后，还要找到应用运行所需的目录、库和配置。这套从根目录展开的内容叫根文件系统。不要在本章列initramfs、只读挂载、重新挂载和制作工具比较。
5. **启动用户程序**：根文件系统可用后，初始化程序启动系统服务和应用。此时读者看到的登录服务或项目程序已经位于用户空间；它们通过内核使用硬件，而不是重新接管启动流程。

## 7. 术语出现顺序

| 先用普通话说明 | 随后给正式名称 | 本章停止位置 |
|---|---|---|
| 统一安排处理器、内存和外设的软件 | 操作系统（OS） | 不讨论操作系统分类与历史 |
| Linux系统中负责管理资源的核心部分 | Linux内核 | 不列全部内核子系统 |
| 内核中与某类硬件打交道的部分 | 驱动 | 不讲驱动模型与总线框架 |
| 程序请求内核服务的统一入口 | 系统调用 | 不列API名称和调用号 |
| 程序的一次正在运行的实例 | 进程 | 不讲进程状态机 |
| 同一进程内部的一条执行路线 | 线程 | 不讲线程库和同步API |
| 多个工作在同一段时间内交替推进 | 并发 | 不把它等同于多核并行 |
| 外设发生事件时提醒处理器 | 中断 | 不讲IRQ实现细节 |
| 给长期数据建立名称、目录和规则 | 文件系统 | 不列文件系统类型 |
| 启动前把内核装入内存的软件 | 引导程序；证据闭合后再给U-Boot | 不讲配置命令 |
| 告诉内核板上有哪些硬件的说明 | 设备树；必要时给DTB | 不出现DTS/DTSI/DTC语法链 |
| 从根目录展开、供系统和应用使用的一套文件 | 根文件系统（rootfs） | 不列制作工具和挂载命令 |

同一自然段首次引入的缩写不超过两个。`OS、API、ABI、VFS、MMU、IRQ、DMA、CFS、IPC、POSIX`不得在一个概念段中排成清单。第1章中的IPC表示网络摄像机，本章若没有必要，不再引入Linux“进程间通信”的同名缩写，避免同词异义。

## 9. 写作门禁

第3章进入正文前必须满足：

- 只保留上述5个二级标题；“处理器”“内存”“中断”“文件系统”“BootROM”等不再各拆一个只有一段的小标题。
- 开头承接第2章的硬件连接，结尾只进入第4章真实Linux观察，不跳到烧录、项目架构或音频。
- 一段只推进一个问题；同一段首次出现的缩写原则上不超过两个。
- “Linux内核”“Linux系统”“引导程序”“根文件系统”职责不混写。
- 进程/线程只建立最小区别，不提前写第11章的调度与同步细节。
- 文件系统只解释目录与长期保存，不出现Luckfox的分区大小、挂载结果或命令截图。
- 启动流程的当前板卡结论必须绑定RV1106官方资料、当前SDK配置或真实启动日志；参考DOCX只能作为写法参考，不能证明boomPI启动状态。
- 图片均标为教学关系图或官方资料图，不冒充板端实测；全章主图不超过3张。
- 机械搜索并人工检查：`本章将`、`我们将`、`可以把`、`就像`、`首先`、`其次`、`值得注意的是`、`非常重要`、`接下来继续`、`后续会`、`至此`。没有具体对象和因果的句子全部删除。
- 正文完成后由技术审校确认启动链和当前镜像证据，由可读性审校检查术语首次出现顺序，由视觉审校检查概念图是否清楚且来源完整。

按这条基线写成正文时，读者应先明白“为什么需要操作系统”，再逐步获得内核、进程、线程、内存、中断、文件系统和启动链这些正式名称；任何具体命令都留给下一章在真实板端出现。

# 第4章无需新增当前板截图的最小改写方案

## 结论

**可以合格，不必为第4章新增 `pwd`、`ls`、`ps` 的当前板截图。**

成立条件只有一个：4.4、4.5 必须明确停留在“认识目录、进程和设备入口”的概念层，不能再让读者此刻输入命令，也不能写成已经在当前板上观察到了某个结果。真实操作统一放到第6章“登录后的测试基线”，并在那里用当前板截图、命令原文和完整输出闭环。

这种安排符合本地参考文档的实际写法。《0.基础概念》和《13.Rootfs Bootfs》会先用连续自然段和示意图解释 U-Boot、内核、根文件系统、目录树之间的关系；只有进入《3.登录》《4.分区信息与 Linux 命令》一类操作内容后，才出现“输入什么—看到什么”的终端截图。因此，第4章可以像前一类文档一样只负责建立关系，但不能保留后一类文档的操作措辞。

## 最小改写边界

本方案不要求扩写第4章，也不要求增加新的板端事实。只需完成以下两处收口。

### 4.4 只解释“目录把对象放在哪里”

本节保留三层内容即可：

1. Linux 只有一棵从 `/` 开始的目录树；这里的“根”是路径起点，不是 root 用户。
2. 用一张教学示意图说明 `/etc`、`/bin`、`/sbin`、`/proc`、`/sys`、`/dev`、`/tmp`、`/run` 各自放什么。
3. 说明这些路径的来源并不相同：有些来自固件，有些由内核运行时提供，`/dev` 则是程序接触驱动的入口。

应删除或改写以下操作式表达：

- “登录后输入 `pwd`。”
- “执行 `ls /` 可以看到……”
- “请在当前板上观察……”
- “本轮目录结果如下。”
- “看到这些目录说明系统已经正常。”

建议把4.4结尾写成纯粹的因果过渡：

> 目录只说明这些内容放在哪里。要继续理解系统怎样工作，还要分清磁盘上的程序文件、正在运行的进程，以及程序访问硬件时经过的设备入口。

这句自然引到4.5，不在一节中途插入课程路线，也不会产生“稍后保证完成”的AI式预告。

### 4.5 只解释“程序运行后怎样找到设备”

本节保留一条连续关系：

> 固件中的程序原本只是静态文件；被系统启动后，它才成为进程。Linux用PID区分不同进程，负责建立用户空间并继续启动其他服务的初始化程序占用PID 1。进程需要使用硬件时，不会直接操作芯片引脚，而是通过内核驱动提供的入口发出请求。许多入口出现在 `/dev` 下，所以称为设备节点。设备节点出现，只说明入口已经建立；硬件能否真正工作，还要经过后面的实际操作。

本节不得再出现：

- `ps` 命令框、模拟输出或“你会看到”的结果说明；
- “当前板PID 1是……”或“本轮进程快照……”；
- 对当前 `/dev` 节点存在情况的无截图断言；
- 把教学示意图写成当前板实测证据。

章末只保留一次后移说明即可：

> 这里先把目录、进程和设备入口的关系连起来。第5章从固件的生成与写入继续往下走；第6章取得稳定的板端登录会话后，再用 `pwd`、`ls`、`ps` 和 `/proc` 核对当前系统，并以这组结果作为硬件测试的起点。

如果4.4已经写了“第6章再执行”，4.5结尾就不要重复同一承诺；整章出现一次即可。

## 真实操作后移到第6章的准确位置

这些命令不宜移到第5章。第5章的主线是 Buildroot、固件烧录和 HelloWorld，把目录树与进程观察插入其中，会打断“生成固件—写入板卡—启动程序”的连续过程。

建议由第6章第一节新增或预留“登录后的测试基线”，位置在以太网、Wi-Fi、显示、摄像头等任何单项硬件测试之前。该节一次完成下列闭环：

| 操作 | 要回答的问题 | 必须保存的证据 |
| --- | --- | --- |
| 登录并保留提示符 | 当前操作对象是不是目标板 | 包含登录方式、主机名或提示符的完整截图 |
| `pwd` | 当前会话从哪个目录开始 | 命令与输出同框截图 |
| `ls /` | 根目录中实际有哪些入口 | 命令与未裁掉的输出截图 |
| `ls -ld /dev /proc /sys` | 三类入口是否存在 | 命令、输出及必要说明 |
| `ps` | 当前有哪些进程 | 命令与进程列表同框截图 |
| 查看 `/proc/1` 或等价信息 | 当前板PID 1对应什么 | 实际命令、完整结果和文字结论 |

这一组不是额外的知识点堆叠，而是第6章所有硬件测试共用的起点：先确认登录对象、目录入口和进程环境，再继续测网络、显示、摄像头等资源。失败恢复也应放在第6章，例如“命令不存在时先记录镜像版本，不立即改系统”“输出与示意图不同不判失败，先保存原始结果”。

## 与参考文档风格是否一致

一致，但要守住两条线。

第一，概念段落必须围绕一个问题连续展开，而不是把 `/etc`、`/proc`、`/dev` 各拆成一个小标题或词条。参考文档的自然节奏通常是“先说明为什么需要它，再解释几个对象的分工，最后把关系接到下一件事”，不是术语百科。

第二，示意图只能帮助读者看清关系，图注应明确写“教学示意”。它不能代替板端终端截图，也不能支撑“当前板已经出现某节点、某进程”的结论。第4章不作这些实测结论，就不欠相应截图。

第4章已有的系统身份实拍如果继续承担“这是当前板运行的Linux系统”这一事实，可以保留；本方案只是取消为4.4、4.5新增操作截图的要求，并不主张用概念图覆盖已有实测事实。

## 不可替代的情形

只要正文保留下面任一内容，本方案就不能使章节合格，必须二选一：补当前板真实截图，或删除该操作/结果断言。

- 要求读者现在“输入、执行、观察、核对”某条命令；
- 给出“预期输出”并把它当作当前板结果；
- 写“本轮PID 1为……”“当前 `/dev` 中已有……”；
- 用重绘终端、示意命令框或概念图冒充实测证据；
- 用“命令成功，所以硬件正常”代替第6章的实际硬件验证。

原因不可替代：这类句子已经从概念解释跨入操作和事实验证。按照AGENTS门禁及《3.登录》《4.分区信息与 Linux 命令》的参考行为，操作必须同时给出前置条件、真实命令、完整结果和失败处理；概念图无法证明当前板状态。

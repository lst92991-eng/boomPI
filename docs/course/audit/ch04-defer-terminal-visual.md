# 第4章延后终端截图的视觉与语气判定

审计日期：2026-08-10
审查对象：第4章 v0.1e 四页结构，以及 `chapter04.md` 中 4.4、4.5 两节。
问题：若 4.4、4.5 不再要求读者当场操作，只解释目录树、进程和设备节点，现有“2 张概念图 + 1 张真实身份图”能否作为概念章通过。

## 1. 结论

**可以通过，但当前正文还差两处语气关闭。**

- 四页结构和三张图的配置可以作为概念章正式通过，不要求为了“截图数量”补 `pwd/ls`、`df/mount` 或 `ps` 终端图。
- 图 4-1 解释 Ubuntu、Buildroot 与板端系统的关系；图 4-2 用一次真实身份截图把概念锚定到当前板；图 4-3 解释根目录中的几类入口。三张图各自只回答一个问题，证据类型也已区分为“教学示意”和“本轮真实快照”。
- 当前 v0.1e 的**视觉结构 PASS**。但是 `chapter04.md` 第 37 行仍写“登录后输入……会看到”，第 47 行仍写“`ps` 可以读取……本轮原始记录中……”。这两句仍把 4.4、4.5 拉回操作/当前观察路径。精确改写后，本章可从“条件 PASS”转为概念章 PASS。
- 延后终端截图不等于取消全书实测。目录、挂载、进程和设备功能应在后续真正需要操作的章节按“动作—截图—结果—判定”闭环；第4章只负责把名词放到正确关系中。

## 2. 17 份原始参考文档支持这一判断的原因

本轮按 `文本合格参考标准` 中 17 份原始 DOCX 的既有直接核验记录、段落/图片统计和逐页行为重新分类，不把操作章的截图密度机械套给概念章。

### 2.1 概念章允许正文和少量关系图主导

- `0.基础概念.docx` 用 U-Boot、内核、设备树、根文件系统四个对象组织概念；21 个段落、4 张图。图片用于解释职责，不要求每个概念都附终端实测。
- `10.设备树.docx` 有 81 个段落而只有 1 张图，说明概念解释能由正文、代码关系和一张关键图承担；不能用“每页必须有截图”作为合格门槛。
- `4.分区信息与 Linux 命令.docx` 有 141 个段落、12 张表、0 张图片。它把命令功能、格式和示例写成文本。新稿不照搬其命令词典，但这份原件证明：参考体系本身并没有要求所有 Linux 名词都用终端图覆盖。
- BQ76952、SC8815、SOC 三章的高信号行为是“从当前问题进入—给正式名称—用关系图或原理图解释—再收回软件边界”，不是为每个概念补一个假操作画面。
- `1.Luckfox Pico Ultra W简介` 与 `13.Rootfs Bootfs` 也会在真实对象/关系图和解释之间切换；图片的职责取决于此刻是认识对象还是执行操作。

### 2.2 只有操作承诺才触发“一步一图”

- `2.镜像烧录`、`3.登录`、`6.文件传输`、`8.SDK 镜像编译`、`9.Buildroot 配置`、`11.SDK 内核配置`、`12.HelloWorld` 的截图密集，是因为正文要求读者点击、输入、等待并判断结果。
- `5.自启动与静态 IP 配置`、`7.交叉编译` 进一步说明：即使参考原件截图少，动作仍需要明确命令和结果；新稿应补证据，而不是复制其缺口。
- 因此，判断标准不是“本章出现了 `ps`、`/dev` 这些词就必须截图”，而是“本章是否要求读者现在执行 `ps`，并据输出得到当前板结论”。若 4.4、4.5 只解释概念，真实目录/进程图不是本章硬门槛。

## 4. 必须删除或改写的当前操作句

### 4.1 章首第 5 行

当前：

> 这一次只读取系统信息：先分清开发电脑和开发板，再沿根目录找到命令、运行信息和设备入口。

问题：“这一次只读取”预告当前操作；后文若不提供目录/进程截图，会形成未闭合承诺。

建议替换：

> 这里先分清开发电脑和开发板，再认识根目录、进程和设备入口之间的关系。网络配置、文件写入和硬件测试不在本章展开。

### 4.2 4.4 第 37 行

当前：

> 登录后输入 `pwd` 会看到当前所在位置，输入 `ls /` 可以查看根目录第一层。

判定：**必须删除。** 这是明确的命令—预期结果句；保留它就需要真实终端截图或至少完整结果块，不能一边延后截图一边继续要求读者输入。

建议用下列概念段整体替换第 37 行：

> Linux 只使用一棵以 `/` 为起点的目录树。它没有 Windows 的 C 盘、D 盘式入口，这里的“根”也不是 root 用户的名字。不同存储、内核运行信息和设备入口会接入这棵树中的某个位置，程序只需从 `/` 开始寻找。

### 4.3 4.4 第 43 行后半

当前：

> 具体挂载和存储读写留到后续章节实测。

这句不是证据错误，但属于课程安排自述。可删去，用当前概念边界替代：

> 这些入口的来源并不相同：有些来自根文件系统中的普通文件，有些由内核运行时提供，还有些对应挂载进来的存储。仅凭目录名不能判断存储来源或读写状态。

### 4.4 4.5 第 47 行

当前：

> `ps` 可以读取当前进程快照；本轮原始记录中，PID 1 名为 `init`。

判定：**必须删除或移到有终端证据的后续操作章。** 这句话同时给出命令和本轮当前结论；虽然原始日志能追溯事实，但本章视觉路径没有让读者共同观察该输出。若本节改为纯概念，不需要为了保留这一个历史快照新增图片。

建议将第 47 行改成：

> 程序运行后，系统用进程记录它的运行状态。每个进程都有编号，进程之间也可能存在启动关系；名称和编号只能说明当前有哪些任务，不能单独证明程序从哪里启动或能否长期稳定运行。

不要在替换句中加入 `ps -ef`、PID 1 或 `init`。这些词一旦重新承担“当前板观察结果”，截图义务也会重新出现。

### 4.5 4.5 第 49 行

当前两句可以保留，但建议把“节点能够被列出”改成不暗示当前命令的表述：

> 设备节点是程序进入内核驱动的一类入口。例如 `/dev/console` 表示控制台入口，`/dev/null` 表示一种特殊字符设备。名字出现在 `/dev` 中，只能说明系统提供了相应入口；它不是硬件本体，也不能替代后续功能操作与结果。

# 第2章《原理图介绍》连续叙事提纲

## 1. 结论与叙事主线

第2章建议只保留 **6 个二级标题**。全章沿一条真实的开机与使用链路推进：

> 5 V 进入主板 → 主控得到稳定电源、时钟和复位 → 从存储器读取系统 → 通过网口或 USB 路线连接外部 → 接收摄像头图像并连接屏幕、触摸 → 最后盘点扩展排针和音频硬件边界。

这个顺序能覆盖原理图的 11 个有效功能页，又不会把每个器件拆成一个小标题。每一节内部都按“眼前的问题/手册提出的条件 → 干净原理图模块 → 为什么这样接 → 留到哪章上板验证”写成连续自然段；这四项是作者的组织卡，不作为学生可见的小标题。

开头直接承接第1章结尾：

> 第1章已经知道各模块放在哪里，也看过上电顺序和 USB 复用的整体关系。原理图还要回答更具体的问题：5 V 怎样变成主控需要的几种电压，系统内容从哪里读出，网口、摄像头和屏幕又分别接到主控的哪组引脚。先用页码地图找到模块，再把手册中的要求与本板电路逐项对上。

结尾只把问题交给第3章“操作系统简介”：

> 原理图说明了硬件打算怎样连接，却不会自己完成存储读写、网络收发或图像显示。下一章从一个实际问题开始：应用程序为什么不必直接控制这些引脚，操作系统在中间替它管理了什么。

## 4. 建议的 6 个二级标题与连续段落逻辑

### 2.1 先用页码地图找到每类电路

正文段落顺序如下，不再拆三级标题：

1. **问题/资料依据**：12 页原理图第一次打开很大，读者最容易犯的错是从 R1 开始追到最后一个电阻。先说明原理图按功能分页，绿色网络名把不同页面上的同名连接接在一起；这一节的依据就是当前原理图和 netlist，不为页码导航虚构器件手册依据。
2. **图片**：放 `assets/schematic-clean/schematic-page-map.png`。图前要求只找页标题；图后指出第7页是空白定位孔页，不是加载失败。正文把 1～6 页归为“让板子启动并保存系统”，8～12 页归为“连接外部器件”，不要逐页念标题。
3. **为什么这样组织**：第2页 U3 是连接中心，但整页缩小后无法读清，因此整页只作导航，后面只放干净模块裁剪；不在原理图上画红框、箭头或编号。
4. **后续验证**：这里不通电，也不出现“测试通过”。读者只获得一个页码索引，随后从第1页的电源入口开始。

自然过渡建议：

> 页码已经找到，最先要看的不是网口或摄像头，而是这些器件怎样得到稳定电源。没有稳定的电、时钟和复位，主控还不能开始读取系统。

### 2.2 板子先要得到稳定的电、时钟和复位

1. **问题/手册依据**：Type-C 提供的是 5 V，RV1106G3 内部各部分却使用不同电压；处理器还需要稳定的节拍和明确的复位条件。手册依据依次使用 RV1106/RV1103 硬件设计指南中的供电、时钟、RTC、复位/恢复要求，EA3059QDR 数据手册，以及 U14/U16 的 TI TLV62568 数据手册。手册截图只截当前段落用到的表或时序，不整页堆参数。
2. **干净原理图模块**：先放 `p01-typec-power-input.png`，说明 Type-C 电源入口、数据线保护以及 5 V 过滤/保护属于三件不同的事；随后放 `p01-power-tree.png` 与 `p01-power-sequence-rc.png`，只用一句回扣第1章已经解释的上电先后。接着放 `p02-main-clock-reset-debug.png`，观察 24 MHz 主时钟、32.768 kHz RTC 时钟、复位按键和调试灯。
3. **为何这样接**：按真实电流和控制关系写。`TYPEC_VBUS_5V` 经过保护后形成 `SYS_5V`；U4 再产生主控所需电压。U14 单独形成 `WIFI_BLE_3V3`，U16 形成经过 F2 的 `OUT_3V3`，避免把所有 3.3 V 消费者混成一条没有边界的描述。24 MHz 给主系统提供节拍，32.768 kHz 用于低速时钟；RTC 电池座、Type-C 插入检测、复位键和 Recovery 键分别说明“断电保持、检测供电存在、重新开始、进入恢复条件”这四类作用。Recovery 键不是普通功能键，不安排学生随手操作。
4. **留到哪章验证**：第5章在有备份与恢复路径的前提下验证 Type-C 烧录和 Recovery 条件；第6章用当前板端启动/身份证据确认系统能正常运行。电源时序是否真正满足手册只能由授权示波器实验确认，不能用原理图计算代替。

本节还缺 3 张干净局部，正式写作前应从第1页补裁：

- RTC 备用电源 U11/U13；
- `TYPEC_USB_DET` 插入检测；
- U14/U16 两路独立 3.3 V 电源及 F2，必要时另补 `VDD_ARM_0V9` 的 0 Ω 连接局部。

术语顺序：先说“同一电压分给一组器件的线路”，再给“电源轨”；先说“给处理器提供固定节拍”，再给“时钟”；本节不展开 PLL、抖动、晶振负载电容公式和电源环路补偿。

### 2.3 系统内容放在哪里，主控怎样读到它

1. **问题/手册依据**：电源和时钟稳定后，主控必须找到长期保存的系统内容。本节只比较焊在主板上的 eMMC 与可拔插的 microSD。手册依据使用 RV1106 数据手册的 eMMC/SDMMC 接口能力、KLM8G1GETF-B041 器件资料和 SD 卡接口规范；BootROM 只引用“支持哪些介质”，不推导优先级。
2. **干净原理图模块**：先放 `p01-emmc-voltage-select.png`，再相邻放 `p06-emmc-device.png` 与 `p06-emmc-support.png`；图后沿 `EMMC_CLK/CMD/D0～D7`、供电、上拉和去耦分成三段解释。随后放 `p05-microsd-card.png`，只观察数据、时钟/命令、供电和插卡检测四组。`p02-main-storage-recovery.png` 只裁取主控侧 eMMC/SDMMC 引脚来源，Recovery 按键不在此重复讲。
3. **为何这样接**：eMMC 使用焊接器件保存固定系统，主数据路径为 8 位；`VDD_EMMC` 通过 0 Ω 选配形成 I/O 电压方案，原理图和 netlist 只能证明当前设计选择，不能代替实物料况检查。microSD 使用可拔插卡座和 4 位数据路径，并带卡检测。上拉电阻给部分信号提供默认状态，去耦电容只解释为“靠近器件稳定供电”，不先讲信号完整性模型。
4. **留到哪章验证**：第5章确认镜像的目标介质和实际启动结果；第6章分别查看块设备、容量、挂载与最小读写。microSD 能否作为启动介质、失败后是否自动回退，仍要结合 SDK/BootROM 文档和当前板端状态另行验证。

本节不重复第1章的“8 GB 标称容量”解释，可用一句交叉引用带过。不要逐个讲 eMMC 的 BGA 球号，也不要把测试点写成让学生短接的操作入口。

### 2.4 网线和 USB 无线链路怎样到达主控

1. **问题/手册依据**：系统要与外部通信，一条路线从主控内部的百兆以太网接口到 RJ45，另一条路线从主控 USB 经选择器到 Wi-Fi、Type-C 或 USB-A。手册依据使用 RV1106 的 Ethernet/USB 接口说明、HR911105A 器件资料、M8800DS2 模组资料和 TI TS3USB3031 数据手册。M8800DS2 与 HR911105A 的制造商资料尚未在章节 sources 中归档，未补齐前不能写超出原理图的性能、射频或蓝牙能力结论。
2. **干净原理图模块**：先放 `p04-hr911105a-ethernet.png`，从 `ETH_TX/RX` 一侧读到带磁性器件的 RJ45 与指示灯；再放 `p03-m8800ds2-wireless.png`，只找 `WIFI_DP/DN`、3.3 V、PWR_KEY 与天线。最后把 `p11-usb-selector.png`、`p11-ts3usb3031-mux.png` 和 `p11-usba-connector.png` 连续放置；U15 手册真值表与 U15 原理图相邻。
3. **为何这样接**：有线部分先说明芯片侧收发信号为什么要经过网口磁性器件再到网线，LED 驱动只解释状态指示。无线部分由 netlist 明确写成 M8800DS2 的 `USB_DM/DP` 接 `WIFI_DN/DP`；当前 SDIO、UART、PCM 等引脚没有形成主控闭合数据路线，因此不能把模组名称中的“蓝牙”直接写成已可用。USB 部分只补证据映射：U15 公共端接 `SOC_USB_DP/DN`，三组端口分别接 Type-C、Wi-Fi 和 USB-A，SW5 与主控输出共同形成选择条件。第1章已讲过二位置开关与 3:1 复用器，本节不再重复比喻或长篇概念说明。
4. **留到哪章验证**：第5章验证 Type-C 烧录路径；第6章分别验证以太网链路、Wi-Fi USB 枚举、USB-A 外设和 SW5 实物方向；第10章才把已通过的网络通道用于配网、服务端和云端链路。蓝牙只有在硬件路线、驱动绑定和当前枚举证据同时闭合后才能下结论。

术语顺序：先说“网线入口里带有隔离和信号转换器件”，再给“磁性 RJ45”；先说“两根一起传输同一组高速数据”，再给“差分对”。MAC、PHY、射频阻抗、USB 480 Mbps 等不影响当前读图的细节后移。

### 2.5 图像怎样进入，屏幕和触摸怎样返回结果

1. **问题/手册依据**：摄像头既要搬运图像，也要接受配置；屏幕负责接收画面，触摸则把手指位置送回主控。手册依据使用 RV1106 的 MIPI CSI、SPI 和 I²C 接口说明，并分别对照实际外接摄像头模组、显示控制器和触摸控制器资料。原理图中的 `SC3336`、`ST7789`、`GT911` 是设计注释或网络命名，不能代替外接模组实物身份。
2. **干净原理图模块**：先放 `p10-camera-fpc.png`。图前要求按用途找三组：搬图像的时钟/数据线、配置传感器的两根控制线、让模组正确启动的电源/复位/主时钟。图后再放 `p12-display-touch-fpc.png`，先读屏幕的 SPI 与背光/复位控制，再读触摸的 I²C、复位和中断；两组信号共用 FPC2，不等于共用同一种通信方式。必要时从 `p02-main-core-interfaces.png` 只补相应主控引脚来源，不展示整页 U3 让读者找针脚。
3. **为何这样接**：图像数据量大，摄像头使用专门的时钟和数据对；配置命令量小，另用两线控制总线。屏幕的画面/控制与触摸坐标返回方向不同，所以原理图把它们分成两组网络。串联电阻、上拉和去耦只解释其眼前作用，不连续引入端接、时序裕量、总线仲裁等新术语。
4. **留到哪章验证**：第8章用真实屏幕和触摸证据确认显示、方向与坐标；第9章确认实际摄像头身份、驱动绑定、采帧格式和真实画面。原理图存在 FPC1/FPC2 不能升级为设备节点已经出现，更不能写成 LVGL 或 V4L2 已经完成。

本节禁止提前出现 `/dev/video*`、`spidev`、帧率、像素格式、设备树节点和 LVGL 对象结构；这些词只有在相应操作章有真实对象可观察时再引入。

### 2.6 40Pin 与音频只确认连接边界

1. **问题/手册依据**：还剩第9页扩展排针和第8页音频电路。它们必须被覆盖，但不能突然把章节主线改成扩展开发或语音实现。40Pin 依据 U7 当前网络和 RV1106 引脚复用/电压资料；音频只依据 RV1106 codec 引脚定义与 FM8002A 数据手册，确认信号方向、供电和外接连接器。
2. **干净原理图模块**：先放 `p09-expansion-40pin.png`，按“电源/地、普通控制、成组接口”三类阅读，不制作 40 行针脚清单。随后放 `p08-fm8002a-amplifier.png` 与 `p08-dual-mic-connectors.png`；图前明确这里只找声音从主控到功放再到扬声器连接器的路线，以及两个麦克风连接器到主控 codec 输入的路线。
3. **为何这样接**：U7 把 5 V、3.3 V、地和 GPIO/I²C/SPI/UART/PWM/PCM 等设计网络引出，部分线路带上拉或串联电阻。原理图标题“尽可能兼容树莓派”只能写成设计目标，不能宣称电气、复用和软件完全兼容。音频输出由 `SPEAKER_LINEOUT` 进入 U8 FM8002A，再接 CN1；U9/U12 是外接麦克风连接器，并通过偏置与滤波网络接向主控的麦克风输入。麦克风胶囊、扬声器都不是主板贴片器件。
4. **留到哪章验证**：40Pin 只在第6章做安全的身份与电压边界核对，真正扩展实验留到第18章二次开发。音频不在本章操作；播放、采集、队列、VAD/唤醒、3A、问答与打断统一留在第14～17章音频阶段，并继续遵守授权 HIL、音量、隐私与 mixer 恢复要求。

本节只允许出现“功放把主控输出送到外接扬声器”“麦克风连接器把输入送到主控”这一级说明。ALSA、采样率、位宽、通道模式、PCM 缓冲、3A、VAD、唤醒词、回声消除和打断全部后移。

## 5. 节间自然过渡与必须删除的套话

以下句子可直接作为各节末尾的因果桥，但不要另设“过渡”小标题：

| 位置 | 建议过渡句 |
|---|---|
| 2.1 → 2.2 | 页码已经找到，最先要看的不是网口或摄像头，而是这些器件怎样得到稳定电源。没有稳定的电、时钟和复位，主控还不能开始读取系统。 |
| 2.2 → 2.3 | 电源、时钟和复位只让主控具备开始工作的条件。复位释放以后，它还要从一种不会因断电而丢失内容的存储器中找到系统。 |
| 2.3 → 2.4 | 系统能够从存储器启动，板子仍然是孤立的。网线和无线模组要把数据送到主控，但它们走的并不是同一套电路。 |

## 8. 写作门禁

第2章进入正文前应满足以下条件：

- 只有上述 6 个二级标题；正文不出现“Type-C 电源”“RTC”“Recovery”“功放”等单段小标题。
- 每组至少形成一次“手册/资料提出条件—干净原理图回应—设计原因—后续验证”的完整闭环。
- 第1章的电源时序计算和 USB 复用概念不再重讲，只用交叉引用承接。
- 原理图使用“连接到、预留、选择、形成”这类设计事实动词，不出现“已经正常、测试通过、可以使用”。
- 外接摄像头、屏幕、触摸、麦克风和扬声器不写成主板贴片器件。
- 音频只占章末一组硬件连接说明，不出现实现流程、命令、设备节点、算法或效果判断。
- 章节末尾自然引到第3章操作系统，不跳到烧录、项目架构或远期语音功能。
- 正文完成后机械搜索：`本章将`、`我们将`、`后续会`、`接下来继续`、`值得注意的是`、`非常重要`、`可以把`、`首先`、`其次`、`最后`、`至此`。每次出现都必须有具体对象和因果，否则删除。

按这个提纲写成正文时，读者看到的应是一条连续的硬件路线，而不是 12 页原理图说明书的目录复述。

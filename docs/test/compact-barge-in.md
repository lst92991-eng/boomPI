## 两阶段，而不是恢复旧四阶段框架

普通提问仍为300ms连续VAD、500ms前滚、700ms句尾静音。播放或自然尾音期间使用同一PCM环，但准入条件不同：

1. 候选：当前语音上下文见过参考，且VAD与去直流后RMS连续满足120ms。仅请求暂停消费TTS，不发送START/CANCEL，不进入录音态。
2. 复核：先见播放线程已送静音的观测及实际参考下降，低参考持续160ms后，再确认60ms近讲。最多复核380ms；成功才进入原有START/PCM/END路径，失败恢复旧回答、丢掉未准入候选并冷却300ms。

候选120ms + 最大复核380ms = 500ms，编译期检查不超过现有25帧前滚。参考下降过慢宁可拒绝，不能扩大历史后仍沿用旧网络容量，或悄悄截掉句首。上述时间是按20ms连续采集帧计数的内部预置，不是实测端到端插话延迟。

没有固定600ms起播禁插话窗口。有声播放未见参考时不放行；音量为0可走普通语句准入。自然播完保留300ms回声上下文，已开始的复核和句首不因Drained直接清空。

RMS门限1843沿用旧版约-25dBFS的量级，参考峰值门限64。它们只是维护者预置，并不能识别说话人。非常短/弱的插话、错误参考、长混响仍可能拒绝或误判，必须实测，不交给学生校准。

## 试探不再“乘零吞字”

播放线程在复核期间直接写48k双声道静音，不消费TTS环，也不把静音送进TTS重采样器。已经送入声卡的旧样本正常播完；因此不能把hold请求时刻当作物理静音时刻。

拒绝后继续原环和转换器历史，正常结束仍flush/drain；确认则直接cancel，不能先解除hold给旧PCM一次复活机会。试探可以插入可听停顿，不保证听感无缝。

hold有500ms单次有效期，重复true不续期；即使应用暂时拿不到采集帧，也不能无限保持静音。该期限在播放循环检查，不是对异常驱动无限阻塞的硬实时保证。请求hold时为后续音频预留700ms环容量；已积压则不暂停消费，让此次复核失败而不是用反复试探挤满播放环。网络突发/长期拥塞仍遵守现有Full和取消语义。

输入线程只增加两个布尔观测：参考活动及已送静音。参考取实际送3A的refL，观测随3A固定20ms块适配延后一帧交付；播放观测在读取前采样。它不是新的硬件时间戳或独立声学校准结果。VAD/Snowboy仍由输入线程独占，不恢复主线程跨线程reset。

## 接口变更

| 接口/字段 | 输入、输出及调用方 | 旧接口去向 |
| --- | --- | --- |
| `speech::update(frame, speaking=false)` | 应用传采集帧及有声回复上下文；返回原Result加hold请求 | 保留普通单参数调用，未增加转发层 |
| `speech::Result::hold_playback` | 仅候选/复核期为true；应用交给播放器 | 新增一个必要控制字段 |
| `playback::hold(bool)` | 应用请求暂停/恢复TTS消费，播放器负责期限和资源 | 不恢复旧set_scale或begin/generation |
| `playback::held()` | 输入线程无锁读“已写静音”观测 | 不恢复完整播放快照 |
| `CaptureFrame::reference_active/playback_held` | 输入线程生成，speech消费，应用不读声学字段 | 不恢复完整原始电平/时间戳结构 |

确认前不设置utterance状态；确认后沿用现有generation隔离、START(supersede)、前滚、实时PCM、END。断点、网络取消、退出均通过原有取消路径清除hold。

## 服务端：只补与插话突发直接相关的有界容量

`session.go`普通命令槽34→96，排队年龄上限800ms→2s；边界槽2、单次provider操作超时700ms不变。

预算为25帧前滚 + 35帧取消等待 + 35帧首包准备/写入等待 + END = 96项，连同边界/在途约2s音频、约64KB量级。预算是上限，不代表主动添加2s延迟，也不能保证任意云端阻塞都成功。超限仍关闭本轮/连接，不能无界排队或提交缺帧语音。测试必须重新构建板端客户端和配套Go服务端；协议保持BPV4兼容。

## 上板验收

先测试人完全不讲话、让设备完整播放多次回复，再测开头/中段插话、短“停”、自然结束附近追问；在实际常用音量与距离下分别记录。不能仅看不再canceled，还要看是否频繁停顿、丢字、重复、漏插话或断线。

本阶段只在主流程记录三种无敏感数据的诊断：

```text
boompi: barge probe
boompi: barge rejected; reference=0或1
boompi: barge confirmed
```

无人讲话却出现confirmed：保留该次条件，进一步核对参考/3A输出。仅反复probe/rejected且听感断续：虽然不再退休轮次，仍不算体验通过。reference=1反复拒绝：重点核对数字回采是否会随实际播放静音下降。若出现原有input discontinuity、offline或playback故障日志，应与语音误触发分别诊断，不把每次取消都归因于回声。

验收结论必须同时包含：无人讲话时回答完整；真实插话接管一次；新语句首尾连续；旧回复不复活；尾播追问及失败恢复无卡死。测试通过范围之外不承诺零自激或任意短词必达。

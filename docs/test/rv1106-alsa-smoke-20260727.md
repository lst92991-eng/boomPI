## 当前 PCM 与 mixer 事实

- 唯一枚举声卡为 card 0 `rv1106-acodec`，capture/playback device 均为 0。
- 实际 PCM 配置名为 `hw:0,0`；名称来自本次板端枚举和 smoke 显式参数，不是产品
  代码默认值。
- Capture 支持 `RW_INTERLEAVED`、S16_LE/S24_LE/S32_LE、2..4 channels、
  8..192 kHz；本次使用 48 kHz、S16_LE、4 channels。
- Playback 支持 `RW_INTERLEAVED`、S16_LE/S24_LE/S32_LE、固定 2 channels、
  8..192 kHz；mono `hw` 打开被 ALSA 明确拒绝，本次使用 48 kHz、S16_LE、
  2 channels。
- 960-frame period 下，4-channel capture 的实际 buffer 为 1920 frames；
  2-channel playback 的实际 buffer 为 3840 frames。两端不能共用一个未经查询的
  buffer 默认值。
- `I2STDM Digital Loopback Mode` 在测试前后均为 `Disabled`。
- 只读记录还显示 `ADC Mode=SingadcL`、`DAC LINEOUT Volume=26`。本次不判断这些
  mixer 值是否适合最终双麦/AEC，也没有修改它们。

Mixer 控件列表证明镜像提供 `Mode1` 候选项，但本轮值为 Disabled，因此本记录不能
证明四通道内容、MIC-L/MIC-R/REF-L/REF-R 顺序、极性、数字参考采样位置或延迟。

## 基础命令 smoke

先分别用 ALSA 工具确认实际参数，再并行执行 1 秒静音播放和丢弃式采集：

```text
arecord -q -D hw:0,0 -t raw -f S16_LE -r 48000 -c 4 \
  --period-size=960 --buffer-size=1920 -d 1 /dev/null

aplay -q -D hw:0,0 -t raw -f S16_LE -r 48000 -c 2 \
  --period-size=960 --buffer-size=3840 -d 1 /dev/zero
```

两进程真正并行运行时，`capture_status=0`、`playback_status=0`。这证明当前镜像能在
上述参数下短时打开并推进 48 kHz 全双工 PCM；它不证明可听播放、采集内容正确、
Mode1、AEC 或长稳。

## boomPI 平台 smoke

交叉构建启用了显式 opt-in target `boompi-alsa-smoke`。部署文件 SHA-256 为：

```text
3b195e36030ed1549f0896a36c8fba0994f6aa15b4d819925f8219a2537fba13
```

板端只在 `/tmp` 运行；设备名、通道数、period 和两端 buffer 均由命令行显式传入：

```text
/tmp/boompi-alsa-smoke-20260727-final \
  --device hw:0,0 \
  --periods 50 \
  --capture-channels 4 \
  --playback-channels 2 \
  --period-frames 960 \
  --capture-buffer-frames 1920 \
  --playback-buffer-frames 3840
```

原始白名单结果：

```text
capture_rate_hz=48000 capture_channels=4 capture_period_frames=960
capture_buffer_frames=1920 playback_rate_hz=48000 playback_channels=2
playback_period_frames=960 playback_buffer_frames=3840
captured_periods=50 rendered_chunks=51 accepted_chunks=137
accepted_frames=48063 eos_chunks=1 capture_failure_code=0
playback_failure_code=0 failures=0
```

判定：

- 50 个 20 ms、4-channel capture period 均取得完整 960 frames；采集数据仅在内存中
  覆盖后丢弃，没有写文件或输出样本。
- 固定上游 `PlaybackRenderer24To48` 生成 50 个 960-frame 静音 prefix，加最后一个
  63-frame FIR drain，共 48,063 frames。
- ALSA 对这些数据实际返回 137 个 positive write prefix；平台层逐 prefix 发布的
  accepted frame 总数严格等于 48,063，最后且仅最后一个 chunk 带 EOS。
- `failures=0`，本轮没有观测到 xrun、超时、代际拒绝或 reference backpressure。

以上计数对应本报告固定 SHA-256 的原始 smoke 二进制。仓库随后把播放提交状态机迁移到
主线 `PlaybackCommitter`，ALSA 侧只保留实现 `PcmPlaybackSink` 的设备适配器。迁移后的
组合已在下节使用独立二进制重新执行板端 HIL；原始实现的 137 个 prefix 仍只属于原始
二进制，不能移用为迁移后组合的计数。

`accepted` 只表示 PCM 已被 ALSA kernel 接受，并且该 prefix 具备进入软件 AEC
reference ledger 的资格；它不是 `played`、DAC 完成或扬声器出声证明。当前主线
committer 负责 accepted sequence/PCM incarnation、partial exactly-once 和
drop/prepare cancel ACK；reference consumer 仍未接入，并且必须按新 epoch 清空旧队列。

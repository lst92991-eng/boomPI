# UI完善与代码可读性梳理

起点：`36c5550d1e6d946fdd42a2497767ca269bb4b33f`，工作区干净。用户于2026-09-16确认该版本语音体验通过，包括当前摆位下的连续对话和中途插话。此次修改在`codex/minimal-non-audio`上继续，音频源码/profile、Go服务端、BPV4、vendor和资源保持2ca0cf6基线。

## 实际修改

- 保留两页，一次创建。语音页独立显示状态、提示、字幕；加入明确的开始/停止按钮、音量数值和静音提示。摄像头状态改为中文，并保留原预览管线。
- Thinking和Speaking的按钮/表情均产生已有Interrupt动作，修复等待回复时点击表情只产生无效Wake的缺口；Idle产生Wake，其余阶段不发送无效命令。应用四态不变。
- 页面按变化更新状态、字幕、滑块。拖动期间不让旧应用快照移动滑块；音量提交仍由UI线程负责，采集线程不做文件I/O。
- UI没有新快照时不重复复制。发现的服务端地址/端口/身份未变化时，不重复写入服务器缓存；发现和TLS身份校验仍然执行。
- 删除应用未使用的Happy显示状态，清理六状态、旧DeviceUi类、配网页/FPS及初始化顺序的过时注释。公开函数和音频接口不新增；模拟器同步移除Happy。
- [阅读说明](../teaching/client-source-reading.md)按启动、采集、语句、网络、播放、UI、摄像头和退出排列，明确每份状态和缓冲的所有者。

## 全局核查范围与保留理由

| 自有生产代码范围 | 核查与处理 |
| --- | --- |
| 客户端入口、配置、启动脚本 | 配置成功后启动，失败共用退出；身份/TLS缓存不被升级覆盖，有限重启和回滚保留 |
| App与所有音频模块/头文件 | 核对顺序、借用PCM、断点、轮次交付、尾播和资源所有权；保持已验收源码，不为排版重新改时序 |
| 网络准备、WSS、编解码 | 清理重复落盘；保留接口绑定、握手/心跳、帧校验与取消后旧结果隔离 |
| UI页面、线程、显示触摸 | 修复动作缺口并减少重复刷新；SPI/I2C寄存器、旋转和恢复规则不变 |
| 摄像头 | 完整帧累积、最新帧交接与显示数组各有职责，保留进程组回收与短轮询 |
| 服务端入口/配置/身份/发现/日志 | 核对资源与凭据边界，不改变学生只配置Key的使用方式 |
| 服务端WSS/session/Qwen ASR、LLM、TTS | 核对有界阻塞、取消、文本/PCM交接；维持运行代码，学生阅读范围不扩展到Go内部 |

这是按职责进行的可读性与生命周期核查，不是声称所有代码都已最小或完成形式化正确性证明。服务端transport仍有一处旧“v3 JSON”注释，实际调用为BPV4文本解析；列为维护说明勘误，本轮保持服务端冻结。

- 匹配LVGL8.2与板端Noto字体实际渲染待机、思考、回答、相机和失败页面，检查中文、布局和缺字过滤。

- 幸狐GCC8.3/uClibc严格交叉构建通过，真实UI与SPI/I2C源参与构建；音频、服务端、协议及vendor/resource固定基线diff为空。

Host渲染和事件测试不代表板端触摸体验。新UI的触摸、字幕和实际摄像头切换由用户在部署后验收；此前通过的是旧UI下的语音体验。

## 1. 最终要交付什么

交付一个功能完整、学生能顺着数据走向阅读的 RV1106 小智客户端，以及与最终代码一致的分阶段复现教材。

学生应当能直接找到下面这些流程，而不必先理解框架：

1. 配置从哪里来，设备和线程按什么顺序启动。
2. 麦克风数据怎样变成一次提问，句首如何保留。
3. 一次提问怎样发给服务端，回复怎样播放并更新字幕。
4. 播放时插话怎样停止旧回答，并把新问题提交出去。
5. 播完后怎样进入三秒追问，断网后怎样恢复。
6. 屏幕、触摸、音量、配网、摄像头分别由谁负责。
7. 出错和退出时，怎样停止线程、释放设备和回收子进程。

完成的含义包含四件事：**结构确实重做、原有功能保持、目标板验收通过、源码确实适合教学**。只有编译通过、main 变短或行数下降，都不足以宣布完成。

## 2. 需求、边界与基线

### 2.1 必须保留的功能

| 范围 | 完整保留的行为 |

| 对话 | 持久 WSS，语音上传、文本/语音回复、播放中插话、手动停止、三秒追问、超时和断线恢复 |

### 2.2 必须遵守的约定

- 官方 SDK、第三方库源码和库二进制不修改；问题在自有调用、桥接和构建中解决。
- 学生声学校准参数为零。硬件事实、已验证的算法常量由内部板级预置维护。
- 服务端是课程配套黑箱。学生一键启动并配置 Qwen/DashScope Key；不要求学习 Go、云 SDK 或 ASR/LLM/TTS 内部编排。
- 客户端协议属于课程：音频格式、握手、轮次、序号、正常问答、停止/插话、超时和断线响应都要讲清楚。
- 模型、音色、地址、发现和 TLS 由配套程序或教师预置。设备上的正常音量操作仍然保留。
- 每次新增、重命名、改变语义或删除跨模块接口，都提交用途、输入输出、调用方及旧接口去向说明。汇报是工作交付要求，不默认变成每改一个函数就停工等批准。

## 3. 整体结构要怎样变化

### 3.1 主要结构决策

| 当前问题 | 目标改动 | 必须出现的结果 |
|---|---|---|
| VoiceAudio → AudioTasks → AudioPipeline 多层协调 | 合并为一个音频运行时；可分源文件，不能继续保留同义转发链 | 生命周期、队列、播放会话只有一个协调所有者 |
| 检测在采集线程，语句整理/插话部分在应用线程 | 检测、句首、语句准入、插话判断集中在采集线程 | 应用只收到完整的语音业务结果，不处理电平/参考信号 |
| 播放 active/ending/done/failed 等在多处镜像 | 一份带轮次的播放会话记录 | END、实际播完、取消和故障具有明确来源 |
| 网络序号校验向音频层重复泄漏 | 线协议解析和会话规则集中在网络模块 | 音频接收已经验证的 PCM，不再解释 START/sequence |
| VoiceLink 同时处理 JSON、协议会话、TLS 和网络维护 | 纯编解码 + 私有协议会话 + WSS 工作线程 | 三种真实责任清楚；不新增一套通用传输框架 |
| 应用主阶段与旧回复收尾互相绑死 | 显式对话步骤 + 独立回复进度 | 播完立刻追问，同时正确接收尾字幕和迟到 Done |
| UI 同时存配置、起进程、操作页面 | 页面/显示任务、设备设置、专用进程适配分清 | UI 表达用户操作，文件与进程生命周期各有归属 |
| 配网 Python 和 C++ 重复面板初始化 | 复用同一自有面板驱动，保留最小首启显示入口 | 首启二维码仍可独立显示，面板寄存器事实只有一份 |
| 测试依赖私有字段/源码拼写，教材描述旧结构 | 测真实行为，教材跟最终源码 | 重构允许改变内部实现，学生读到的就是运行的代码 |

### 3.2 建议责任图

```text
main：配置 → 初始化 → 显式循环步骤 → 退出
  │
  ├─ 对话流程：监听、提问、回复、追问、停止、断线
  │    ├─ 音频运行时：采集线程 + 播放线程
  │    │    ├─ 采集侧语音处理：唤醒 / VAD / 句首 / 插话
  │    │    └─ ALSA / 重采样 / Rockchip 适配 / Snowboy ABI 桥
  │    ├─ 网络连接：WSS 工作线程 + 协议会话 + 纯编解码
  │    └─ 设备界面：LVGL 线程 + 页面；按需摄像头
  │
  └─ 设备设置与平台配套：配置存储、显示触摸、受控子进程
```

建议沿用现有职责目录，以减少迁移噪音：`application/`、`audio/`、`network/`、`ui/`、`config/`、`platform/`。可以把 `audio_runtime.cpp` 分成采集、播放、语音处理文件；这只是一个所有者的不同实现部分，不能每个文件再加一层管理类。

名称暂用 `Conversation`、`AudioRuntime`、`ProtocolSession`、`DeviceSettings` 表达职责，不要求全部成为类。无状态运算用普通函数；需要独占线程、设备或协议上下文时才考虑小型对象。只使用一个实现的流程，不建立继承层级、工厂或接口注册表。

### 3.3 main 和源码阅读形态

main 的正常路径目标为几十行，且读者能看到以下顺序。这里是阅读草图，不是新增 API 或可编译提交：

```text
读取设备设置
安装退出信号
打开音频、网络和界面
初始化对话进度

循环，直到退出或不可继续的错误：
    优先处理停止/连接失效，检查已到期的工作
    处理其余用户操作
    接收服务器回复并交给音频/字幕
    读取语音结果，复核期限和输入身份，再发送提问
    处理本轮产生的收尾工作
    发布界面状态
    等待下一次工作机会

停止对话输入和网络会话
关闭音频线程、界面及其子进程、网络线程
报告结果并退出
```

辅助命令解析放入命令入口实现，不塞满正常语音路径；不把整个生命周期移进 `RunEverything()` 换取短 main。每轮各来源处理量有上限，停止/断线控制优先，不允许收不完的网络 PCM 饿死用户停止或语音输入。循环等待采用现有可说明的有界机制，不新增通用事件循环框架。

任何可能等待的读取返回后，都要再次核验 episode、generation 和截止时间，过期的开口不能因为已经读到 PCM 就获准上传。

显示/字体/UI 初始化失败时提示并继续语音，音量仍从设置读取或使用默认值；音频或网络工作线程无法启动才走初始化失败收尾。网络暂不可达属于 Offline 与重试，不等于线程启动失败。运行中 UI 失败只回收自己的资源。退出信号只置位，不在信号处理器里操作设备。具体使用小型资源对象还是清晰的集中收尾，在 P1 用真实入口样稿比较，不能为追求“零类”复制多份清理逻辑。

## 4. 线程、状态和通信的所有权

### 4.1 谁能改什么

| 执行上下文 | 独占写入的事实 | 不应承担的工作 |
|---|---|---|
| 主线程 | 对话主阶段、wire generation 分配、用户意图、追问窗口、回复进度 | ALSA 阻塞读写、dBFS 判断、TLS 回调内部状态 |
| 采集线程 | 采集设备、输入转换器、3A、唤醒/VAD、句首历史、插话探针、输入 episode | 网络发送、文件写入、界面绘制、等待播放 drain |
| 播放线程 | 播放设备、输出转换器、实际播放阶段、drop/drain 收尾 | 分配对话 generation、判定用户是否说话 |
| 网络线程 | socket/TLS/WebSocket、握手/心跳/重连；协议会话按同一受控边界访问 | 操作 LVGL、运行音频算法 |
| UI 线程 | 所有 LVGL 对象、页面和触摸映射 | 复制对话状态机、直接更新算法状态 |
| 摄像头线程 | 拉取完整帧、预览进程生命周期 | 改写 LVGL 对象或对话状态 |

网络发送准入可继续由短锁保护的会话操作同步完成，socket 工作仍由网络线程执行。不能为了让所有列看起来只有一个线程就把全部操作改成异步并新增应答框架。

两条音频线程是因为采集与播放有各自阻塞 I/O；保留这个起点。只有真板测量表明算法耗时影响持续采集，才评估第三条处理线程及新增队列/延迟成本。

### 4.2 线程通信与进程通信分别处理

大多数音频、网络和 UI 之间是同一进程内的线程通信；摄像头、配网辅助程序才涉及进程通信。统一的是容量、所有权、取消和错误约定，不强行统一成一种“万能 IPC”。

| 交接 | 最小机制 | 容量与失败行为 |
|---|---|---|
| 采集 → 应用 | 有界 PCM 存储 + 语音批次描述 | 按 PCM 帧计算容量；开始与句首整体发布；满时取消该输入并报告断点 |
| 应用 → 音频控制 | 产品专用小命令记录，帧边界生效 | 首版可保留有限等待/应答；过期不能当成功；不通过偷读其他事件等待完成 |
| 网络事件 → 应用核验 → 播放 | 有界 TTS FIFO | 保留 75 槽起点；满则终止该回复，不能覆盖中间帧 |
| 音频 → 应用完成/错误 | 带 episode/generation 的独立状态记录 | 不依赖 PCM 到达或有空位；完成原因明确；终态保留到消费或明确退休 |
| 应用 ↔ UI | 小型一致快照 + 有界用户动作 | 音量连续拖动可合并最新值；停止动作不能被随意覆盖 |
| 摄像头 → UI | 最新完整帧快照 | 预览可以替换旧完整帧；半帧不发布；错误清旧帧 |
| 应用 → WSS | 会话准入后进入有界发送队列 | 预留控制容量，保留 STOP 和替换轮次的先后关系 |
| 摄像头/配网子进程 | 明确 stdin/pipe/退出码与所属进程组 | 超时、取消、回收都可观察；不创建通用作业调度器 |

语音结果环的物理容量先以最多 40 个 16 kHz PCM 帧估算，PCM 为 25 KiB，至少能接纳最多 32 帧历史的一次放行。物理容量不是各级都可同时占满的许可：准入后的采集结果、应用待交付、网络及 WebSocket 待发 PCM 合计不超过 40 帧/800 ms。P1 优先以简单固定分区实现，只有固定分区不足以容纳已验证突发时，才采用一份共享待发帧额度；转移不重复计数，取消正确释放，发送边界核对库内待发字节。两种方案只选一种进入产品，不构建通用流控层。未准入的句首历史另计；准入瞬间整个历史批次必须获得容量，不足就明确取消，不能截掉句首。不能建“64 个批次，每个批次都装 32 帧”的大数组。

episode 由采集线程唯一分配。应用提交监听模式/取消意图，采集在帧边界切换 episode 并在有界应答中返回；应用发出取消时立即停止接纳旧 episode，只有收到有效监听应答后才接受新值。应答超时及迟到应答不能重新激活已取消的监听。episode 描述本地输入边界，wire generation 描述服务器对话轮次，两者不能混为一个数字；这属于实现事实，不是学生配置参数。

上述应答路径用于普通监听。播放中自主确认插话时，采集自行分配新 episode，把 Barge 原因、被打断的旧 generation、新 episode 和句首 PCM 整体发布；应用核验旧轮次仍可接纳插话、批次未被后续取消/退休淘汰后直接接受新 episode 并提交替换提问，不再调用 Listen 或等待其应答。后续 PCM 沿用该 episode，避免再次初始化清掉已经确认的人声与句首。

## 5. 音频模块：重新组织整条处理流程

### 5.1 采集与语句处理

目标代码按下列步骤排列，每步能看到输入和交付对象：

```text
ALSA 读取 48 kHz 四通道 20 ms
→ 四通道联合降采样
→ 取 mic0、mic1、refL 进入 Rockchip 3A
→ 得到带对应元数据的 16 kHz 单声道帧
→ 唤醒 / VAD / AEC 保护
→ 维护句首历史、语句准入、插话探测
→ 交付“开始原因 + 连续 PCM + 是否结束”的语音批次
```

将 `VoiceAudio` 中语句整理和插话逻辑迁入采集侧私有处理部分，与 `SpeechDetector` 形成一个声学状态所有者。删除采集发布判定、应用再清判定、再命令检测器复位的来回交接。

应用只知道“开始了一次输入”“这些连续 PCM 属于它”“它结束了”“它替换哪次播放”。不再读取声学阈值、reference 电平或厂商结构体。

待机唤醒先产生不带 PCM 的 Wake 通知，再由应用打开监听。语音读取可以返回 Wake、语音批次、可恢复 Gap 或空；设备/算法致命错误通过独立健康状态读取，不依赖下一帧到达。不得把全部结果强塞进必须含 PCM 的结构。

### 5.2 播放

```text
网络交付已经验证的 TTS PCM
→ 一次入队操作建立/追加播放，末帧同时发布 EOS
→ 满足首播或补水条件
→ 升采样、音量、限幅、复制双声道
→ ALSA 写入
→ 正常结束 drain；取消中断后 drop
→ 发布带 generation 和原因的完成结果
```

把 `BeginPlayback → QueueReplyFrame → EndPlayback` 合为 `PutReply(TtsFrame)` 一类的操作，减少调用顺序组合。保留设备边界的尺寸、容量、当前 generation 和 EOS 后拒绝追加检查。

线协议 START、sequence、短尾合法性由网络层负责；删除音频中的第二、第三份 wire 校验前，必须证明所有生产入口都经过该路径，且 FIFO 不静默丢帧。

网络送完并不代表扬声器播完。正常 drain 与取消 drop 的语义不能合并；ALSA 文档也区分等待待播帧完成和立即丢弃待播帧。[ALSA PCM API](https://www.alsa-project.org/alsa-doc/alsa-lib/group___p_c_m.html)

### 5.3 必须保留的算法与时序事实

| 事实 | 重构要求 |
|---|---|
| 采集 | 48 kHz、S16_LE、4 通道 `[mic0,mic1,refL,refR]`，每 20 ms 为 960 个采样时刻 |
| 通道对齐 | 四通道联合降采样；双麦和参考不能分别产生不同时间轴 |
| 3A | 16 kHz 三路输入、单声道输出；只用 refL，因为左右播放相同；原始四路仍可供诊断 |
| 分块 | 产品每帧 320 样本，vendor 每块 256；四产品帧对应五次 vendor 调用，保留 FIFO 余数 |
| 延迟 | 现有 320 样本预置带来一产品帧延迟，PCM/时间戳/原始电平/reference 必须对齐；不能只移动声音 |
| 重置 | 普通 Listen 不重建 3A；真实 XRUN/采集断点才成组复位转换、3A 与检测历史 |
| 句首 | 25 帧、500 ms；未准入历史可以滚动淘汰，已经准入的 PCM 不得丢弃 |
| 语音准入 | 起始 120 ms、结束 700 ms；追问准入另有 400 ms，不能因为都叫计数器就合并 |
| 播放预置 | 75 槽/1.5 s；首播 180 ms；缺包 30 ms 宽限后重蓄 40 ms，先保持基线 |
| 短尾 | 24 kHz 完整帧 480 样本，末帧 1～480；保留现有补零策略，另测转换器滤波尾部是否完整 |
| AEC | 600 ms 预热从真实硬件参考出现开始，不能被网络蓄水提前消耗；自然结束保留 300 ms 尾音保护 |
| 音量 | 默认 60%；0 音量旁路、恢复后重新武装；限幅和饱和保留 |
| 调度 | capture FIFO 40、playback 30 作为基线；权限不足告警并退回正常调度；只有测量后调整 |

内部保持 sensitivity 0.7、准入 −30 dBFS、插话 −25 dBFS、vendor AGC 关闭和已验证的算法 feature mask；这些事实不变成学生需要填写的配置。

插话流程完整保留：120 ms 候选 → 临时静音后续输出 → 参考连续低 60 ms（等待最多 300 ms）→ 清尾音 60 ms → 近讲确认 60 ms。失败恢复播放并冷却；确认则停止旧播放，保留已确认人声和句首，再交应用建立新轮次。

临时 gain=0 不代表声卡缓存或房间回声已经消失，所以仍必须观察真实 reference；不把“静音探测”未经验证地改成“暂停 TTS”。缺参考保护和确认插话后的 VAD 历史保留都属于功能。

新一轮播放必须在旧一轮跨线程中断已实际发出、播放线程已收尾、采集侧 AEC 已武装后才 prepare/出声。不能仅在锁内置取消标志后锁外随意 drop：迟到的旧中断可能伤到新一轮。P1 选定有界停止应答与设备复用屏障；终态未被消费或明确退休之前不能被下一轮悄悄覆盖。自然结束、取消、故障有不同终态，只有自然播放完成触发正常追问。锁内只复制有限记录，不调用 ALSA、3A 或 drain；不用大结构原子代替一致快照而引入未知 ARM 运行库依赖。

## 6. 网络：协议事实只解释一次

### 6.1 三个责任

1. **纯编解码**：hello、stop、文本事件和二进制帧编码/解码；不依赖 socket，不 include 整个公共 VoiceLink 定义。
2. **协议会话**：握手后的输入/回复进度、轮次退休、连续序号、END 约束、发送准入；可以是网络模块私有的小对象。
3. **WSS 连接工作**：连接、TLS/SPKI、回调、poll、心跳、重连和网络准备。

公共网络入口仍尽量只有一个。不能为这三个责任分别增加公有 manager、可替换 backend 或额外线程。

发现结果使用 `ServerEndpoint{address, port, spki}` 等真正表达端点的数据；不拿一个缺失设备 UUID 的整份客户端配置冒充端点。设备设置直接含端点，不再来回构造内容相同的 LinkConfig。

### 6.2 保持线协议兼容

协议规范以仓库 `protocol/protocol-v2.md` 和既有 fixture 为准，本次不改服务端协议以迁就客户端结构。

- WSS `/ws`、端口 17806；UDP 17807 发现 `BOOMPI_DISCOVER_V2`。
- hello 携带合法 UUID 和固定教学口令，收到 ready 后才能开始业务。
- BPV2 二进制头为 16 字节，大端字段，reserved 为 0，generation 非零；START/END/SUPERSEDE 的位置、序号与方向规则保持。
- 上行 16 kHz，每 20 ms 640 字节；下行 24 kHz，完整 PCM 帧 960 字节，短尾只在合法末帧出现。
- START 与 sequence=0 对应；序号连续；END 只出现一次且之后无音频；SUPERSEDE 只用于上行 START。
- 老轮次事件忽略，越过当前合法轮次的事件拒绝；generation 用尽按协议重建连接，不能回绕复用。
- JSON 的类型、重复字段、未知字段、UTF-8、长度和取值约束集中在编解码边界；保留 8192 字节消息上限与 4096 文本上限等现行约束。
- stop 使用新 generation，含明确 retract 语义，不等待 cancel ACK。

### 6.3 取消和队列顺序

应用是 wire generation 的唯一分配者，当前代码已经如此，不能把重构描述成“修复多个分配者”。网络会话保存的是合法范围与退休边界，音频保存的是设备正在播放哪个轮次。

新普通问题与插话都由会话的“开始输入”操作生成首帧标记，应用不在每一帧手工计算 START/sequence/SUPERSEDE。开始输入必须与首帧 PCM 一起准入，不能先提交无 PCM 的 START 或切代状态，再等待后续 SendInput。

退休旧轮次时，只删除旧普通 PCM；已经排队且仍必要的 STOP、START|SUPERSEDE 必须按顺序交给服务器。控制容量单独保障，控制/退休事务无法有界准入时才使连接失效并重建，不能假装停止已经送达。普通 PCM 背压则拒绝该帧、以 STOP 取消本轮并进入追问；STOP 成功时不强制断连。断线后丢弃半句，恢复不重播旧录音。

协议的 800 ms PCM 缓冲量与实现的 800 ms 待发滞留期限分别验证，不能混同“采样时刻距现在多远”。准入前 pre-roll/插话历史有其声学长度，准入后的排队时间从交付开始记录；转移到后级不能重新计时。控制消息预留容量并有发送期限，不按 PCM 帧硬折算。P1 将各级实际容量换算成字节和毫秒，P8 验证“最大历史批次＋已有网络积压”，防止两个满窗口叠加。

## 7. 应用：把每条业务路线写出来

### 7.1 主阶段与回复收尾分开

初始方案保留 Offline、Idle、Listening、Uploading、Waiting、Speaking 六个可解释主阶段。它们描述用户当前能做什么。新增或整理一份 `ReplyProgress` 描述当前/上一回复的 generation、服务器 Done、实际播放进度和独立收尾期限。

这不是要求所有状态都保留，更不是多建一套对话状态机。目的是不再以“已经 Listening”推断“旧回复绝不可能还有尾字幕”。P1 通过事件表检查每个字段的独立含义，删除能可靠推导的镜像。

### 7.2 八条必须直接读懂的流程

| 流程 | 显式步骤 |
|---|---|
| 启动 | 读设置 → 打开设备与线程 → 建链握手 → 显示可用状态 |
| 唤醒/点击 | 接受唤醒或点击 → 打开本地监听 episode → 声学准入后分配 generation → 发送句首与后续 PCM |
| 一句说完 | 最后 PCM 与 END → 等回复 → 更新字幕/播放 → 真实播完开启追问 |
| 插话 | 音频确认近讲并停旧输出 → 应用核验旧 generation/episode → 新 generation 的 START\|SUPERSEDE → 继续新问题 |
| 手动停止 | 停本地输入/播放 → 新 generation 的 STOP，按原行为决定 retract → 退休旧事件 → 回到明确页面/阶段 |
| 追问 | 播完立即开放 3 秒 → 新语音准入则普通 START → 窗口结束且没新问题则 Idle |
| 断线/超时 | 终止相应轮次 → 清理不再有效的 PCM/回复 → 显示可理解提示 → 按连接策略恢复 |
| 退出 | 不再接受新输入 → 通知各线程/子进程停止 → 解除阻塞 → 回收资源 → 返回退出结果 |

“一条路线清楚”不意味着把整条路线写成一个几百行函数。一个步骤可以调用真实的协议/设备操作；只有转发、改名、再转发的调用不保留。

### 7.3 播完、Done 和尾字幕的准确时序

| 事件顺序 | 目标行为 |
|---|---|
| PlaybackDone 先到 | 应用观察到本轮真实播完通知后立即 Listening，以同一单调时钟 now +3 秒为截止；旧回复上下文暂留 |
| 尾 Text 在追问期到达 | 仍属有效旧回复则追加字幕，不延长追问窗口 |
| 追问窗口先结束，尾 Text 后到 | 回到 Idle；旧回复可在独立收尾期限内接收，不重开监听 |
| Done 晚到 | 只完成旧回复收尾，不重开、不延长追问 |
| 新问题先开始 | 退休旧回复接收资格，旧 Text/Done 随后忽略；已经听完的回答使用普通 START 保留历史 |
| 播放中确认插话 | 停旧播放，以 START\|SUPERSEDE 撤回未听完回答并发新问题 |
| Done 先到 | 仍等实际播放完成，再开追问 |
| 纯文本/空回复 | 没有 PlaybackDone；由 Done 开一次追问 |

追问起点沿用当前“应用观察到本轮 PlaybackDone”的语义，不回推硬件完成时间，不以网络 END/Done 代替实际播放完成。应用延迟消费时以观察时刻建立一次窗口；已经退休轮次的迟到完成不得开启窗口。这项选择明确避免引入一套未被原需求要求的跨线程物理时间戳接口。

旧回复仍有效且收尾超时时，退休其接收资格；需要远端收尾则使用新 generation 的 STOP、`retract=false`，保持当前 Listening/Idle 和追问截止时间。新问题先开始时旧超时直接作废；同一循环内也按这一先后核验。不能复用“取消输入并重开追问”的整套操作。`HasActiveTurn()` 不能仅从主阶段推断全部收尾责任。

### 7.4 时间与停止策略的基线

| 规则 | 保留值或动作 |
|---|---|
| 唤醒监听 / 追问 | 6 秒 / 3 秒；到期尚未准入则回 Idle |
| 输入 | 墙钟上限 60 秒，媒体帧数上限也为60秒；缺帧/等待超时使用STOP，不能伪造正常END |
| 回复 | 空闲30秒、总上限300秒；文本到达不重置总上限 |
| 尾播 | 音频END后最多3秒等待实际收尾；尾字幕不能延长这项期限 |
| 网络 | WebSocket握手/hello为5秒量级；每5秒心跳、pong等待5秒；重连退避从0.5秒到8秒，沿用基线 |
| 手动停止Waiting/Speaking | STOP撤回未完成回复并进入追问；本地先停止相关输入/输出 |
| 普通上传背压/上传超时 | STOP、retract=false；成功后追问，控制发送失败才Offline |
| 播放中可恢复故障/超时 | 停本轮播放，STOP、retract=true，然后追问；不可继续的音频设备错误退出 |
| 旧回复已播完后的收尾超时 | 按7.3节保留历史收尾，不重开追问、不取消新输入 |

媒体时长、网络等待、播放 drain、追问窗口是不同期限，各自保留单位和作用域。P1 对照当前源码逐项登记停止策略，不能把所有超时统一成断线。

这部分是需要通过 fixture 复现、确认并实现的目标，不冒称目前已经修复。若发现现状与原有预期不一致，记为行为差异并单独说明，不借重构静默改变体验。

## 8. UI、配置、硬件胶水与工具链

### 8.1 界面和摄像头

- `DeviceUi` 只组织显示端口、页面生命周期、快照、动作和线程循环；配置存储及子进程底层操作移出。
- 显示、字体或UI不可用时语音继续；运行中故障只回收UI资源，正常音量加载不依赖屏幕成功初始化。
- `LvglScreen` 按页面创建、页面更新、操作回调排列；不复制主对话状态。保留中文/UTF-8 边界、缺字处理、音量拖动预览与提交保存。
- 显示触摸层直接表达矩形、像素、坐标；LVGL 类型转换留在显示端口。ST7789/GT911 硬件事实不因重排而随意改动。
- 摄像头先保留已验证管线：`video14` 采集 25 FPS，转换为 5 FPS、320×180 RGB565 预览；不无依据改写成全新原生媒体框架。
- 拉流按“启动 → 拼完整帧 → 发布最新帧 → 停止并确认退出”写；首帧约 2 秒、后续完整帧约 1 秒期限保持，收到零碎字节不能无限延长期限。
- 快速进出页面、失败、取消都清掉旧帧并释放相关资源；状态与帧通过一致快照交接。

### 8.2 设置与首启配网

统一设备设置的读取、校验和持久化归属：UUID、已保存 Wi-Fi、服务器端点/SPKI、音量。不同文件格式可以保留，不强迫把凭据和全部设置装进一个大文件。

shell 的 allowlist 读取与 C++ 的字段语义校验职责不同，两者都可能必要；不能用 `source client.env` 省代码。音量拖动只改运行值，提交时保存，写入失败可提示且保留可用运行值。

Python 配网只负责表单和凭据交付；二维码显示使用共享自有面板驱动的最小辅助入口。必须同时验证客户端关闭时首启显示、客户端运行时 `--no-panel` 配网，不能让两方同时初始化面板。

保留配网 owner 锁与 clientctl 控制锁的职责，P1 明确交接顺序。AP热点/STA普通Wi-Fi切换按具体网卡和受管服务身份接管与恢复，替换盲目 `killall wpa_supplicant`；竞争失败者不能清理胜者的配网服务。成功、取消、失败及 wrapper 异常退出后，都要停止属于本次配网的服务并恢复应有网络状态。这部分由配网脚本和网络准备共同完成，不能仅靠C++子进程helper。

### 8.3 胶水按原因放置

| 原因 | 最小放置位置 | 不要扩散到 |
|---|---|---|
| Snowboy 旧 C++ ABI | 独立桥接源与独立编译目标；PCM、整数、不透明句柄跨界 | 整个客户端的 ABI 宏或 STL 接口 |
| Rockchip 分块/厂商结构 | 自有 3A 适配实现 | 应用层、公共 UI 头 |
| ALSA/显示触摸硬件约束 | 自有平台驱动及板级预置 | 各业务流程重复配置 |
| 外部摄像头/配网进程 | 二者实际共用的小型 Linux 进程适配 | 通用任务、插件、事件总线 |
| SDK、sysroot、交叉编译 | 教师 SDK 清单、CMake imported target 和工具链 | 运行时 ifdef、学生逐项填写路径 |
| 运行权限 | 教师部署预检与必要运行提示 | 应用自动 sudo、递归 chmod、修改官方 SDK |

子进程适配明确自己创建的进程组，处理取消、有限等待和组内残留。组长退出不等于后代退出；`waitpid` 回收子进程与向进程组发信号是不同操作。通用起停只处理本程序拥有的进程；配网对系统STA服务的明确接管走8.2节专用交接。不能盲目杀同名进程，也不能假设普通 `waitpid` 能回收全部孙进程。[Linux kill(2)](https://man7.org/linux/man-pages/man2/kill.2.html)、[Linux wait(2)](https://man7.org/linux/man-pages/man2/waitpid.2.html)

### 8.4 编译和完整配套发布

教师通过一个 SDK 根目录/清单预置编译器、sysroot、算法库、模型和运行依赖；学生正常构建不做声学校准，也不解决十几条路径。构建预检用明确的缺失项和修复位置提示权限、loader、架构或 noexec 问题。

Snowboy 的 `_GLIBCXX_USE_CXX11_ABI=0` 只作用其桥接目标；异常留在桥接边界。Host 与目标源由 CMake 选择，不在生产算法中增加测试宏。私有构建配置可改，官方 CMake/头文件/库不能改。

扩展现有发布脚本和 `clientctl update`，按版本生成完整清单与 staging：客户端 ELF、启动/配网脚本、必要资源、依赖库闭包、协议及配套服务版本、哈希。验证通过后激活，保留旧版整套文件；配置迁移先备份，失败可回退。只替换 ELF 的旧流程不能作为整体重构后的正式升级保障。

P1提出、P7落实版本目录、稳定启动入口、激活边界和配置恢复顺序，覆盖当前跨 `/userdata`、`/usr`、`/etc` 的布局；不能声称几次跨目录复制是一次原子激活。断电中断后启动入口能选择一套完整版本或恢复旧版。清单区分包内文件与教师已预装依赖的版本/哈希，依赖闭包检查不意味着把私有模型/官方库复制进源码仓库。Host模拟包/迁移通过，与P9真实ARM包、BusyBox及板端文件系统回退通过，分别记录。

检查分层：配置/依赖/进程状态 → 模块就绪 → 黑箱握手 → 问答及停止体验。离线网络不能被误判为安装损坏；“进程活着”也不等于产品正常。

## 9. 拟议跨模块接口及删改方向

本表是设计接口预算，名字不是最终承诺。只为当前功能设计操作，不增加通用基类。P1 给出精确头文件、所有权、返回类型和同步语义；后续每阶段报告实际差异。

| 边界/拟议操作 | 输入 → 输出；调用者 | 旧接口去向与必要性 |
|---|---|---|
| 设置 `Load`、`SaveWifi`、`SaveVolume` | 设置文件/明确字段 → 值或阶段错误；main、配网入口、UI 提交 | 收拢散落加载与持久化；不重复包装现有保存逻辑 |
| 音频 `Open/Close` | 内部板级预置 → 启停结果；main | 合并 VoiceAudio/AudioTasks/Pipeline 三套生命周期协调 |
| 音频监听控制 | 监听模式/取消意图 → 生效后episode或失败；应用 | capture唯一分配episode，应用取消立即拒绝旧结果；明确帧边界和有限应答 |
| 音频 `ReadSpeech` | 消费预算 → Wake/SpeechBatch/空/Gap；应用 | 唤醒可不含PCM；开始与句首不能拆失；语音结果不混入播放终态 |
| 音频 `ReadStatus` | 消费进度 → 健康状态、generation及播放终态原因；应用 | 无PCM时致命故障也可达；终态保持到消费或明确退休，不被下一轮覆写 |
| 音频 `PutReply` | 已验证 TtsFrame → 接收/满/过时/错误；应用接收回复步骤 | 合并 Begin/Queue/End；末帧和 EOS 一次发布 |
| 音频 `StopReply`、`SetVolume` | 目标 generation/音量 → 明确执行状态；应用、UI 意图处理 | 保留当前真正需要的控制，不返回混淆满队列与断线的 bool |
| 网络 `Open/Close`、`ReadEvent` | 设备身份、端点/消费预算 → 连接及回复事件；main、应用 | 保留一个公共连接入口，内部拆真实职责 |
| 网络 `BeginInput/SendInput/Stop` | generation、普通/替换意图、PCM/停止语义 → 准入结果；应用 | 从应用移走逐帧 flags/sequence；退休与队列提交在同一会话事务内 |
| UI `Open/Close`、`PublishView/ReadAction` | 小快照 → 用户意图；main、应用 | 保留真实边界，去掉存储和进程实现细节 |
| 平台受控进程操作 | 固定业务 argv、pipe、所属组 → 启停结果；摄像头、配网 | 替换散落起停代码；只有两个真实调用者需要的能力 |
| 私有 codec / DSP / 转换器 / ABI 桥 | 字节、PCM、窄数据结构 → 处理结果；所属模块 | 保留真实边界，尽量从公共 include 移为私有依赖 |

对话步骤是应用模块内部函数，不因为拆步骤就全部放进公共头。只有确实被 main 使用的入口才跨文件公开；必要测试时钟可保留一个简单注入点，不建立 clock service。

共享类型限于不同模块都真正理解的事实，如 PCM 格式、TtsFrame、SpeechBatch、UiView、ServerEndpoint。禁止为了统一命名再造多种字段相同的 AudioData/AudioPacket/AudioMessage。

错误处理按边界分清：期望的空结果、过时结果、背压/满、可恢复断线、不可继续的设备错误。采用简单枚举与简短阶段信息；不建通用错误框架，不逐轮打印成功状态。同一故障由责任边界报告一次，正常问答不持续刷调试统计。

代码格式沿用根目录 `.clang-format`、一行一个语句、条件/循环带括号。拟采用一致的 C++ 动作命名与小型值类型，字段用 `snake_case`，数值名保留 `_ms`、`_frames`、`_dbfs` 等单位；确有需要的 C ABI 遵守原契约。最终命名规则在P1样稿统一确定，不机械给所有函数加前缀、不一边重排一边维护多套同义命名。注释以简短中文解释步骤、硬件事实、所有权和时序原因，不重复翻译每一行代码。

每完成一个实质工作包，汇报：

1. 哪些生产流程已经接入新实现，哪些还在旧路径。

4. 同口径文件数/ELOC、最大的阅读负担、必要内存和延迟变化。
5. 已运行的行为检查、尚缺的 SDK/真板/人工证据。
6. 下一工作包及剩余完整范围；只有 P10 完成才能宣布整体交付。

不把零碎改名按文件逐条刷屏；按真正的责任变化报告。新增接口需要先形成具体说明再接入，不因已有授权而重复询问可继续与否。

## 12. 验证计划：功能与可读性分开通过

### 12.1 测试策略

复用现有 CMake/CTest、Python、协议 fixture 和 HIL 入口。Host 测试尽量使用新生产对话、协议、音频运行时、转换和声学策略；只在 ALSA I/O、网络端点、时间和厂商算法窄边界替换。

不能把整个 AudioRuntime 换成理想假对象后，宣称线程/取消/队列验证通过。UI 至少要真实页面交互与图像证据；编译对象库只是编译检查。仅检查代码里有某个字符串的测试，不能代替摄像头退出和配网释放设备的行为测试。

已有有效场景保留并迁移；不为每个内部 helper 增加一份单独测试程序。ASan/UBSan 检查与确定性并发调度用于新增并发边界；并发检查工具可用时补充，工具不能运行时如实说明。

### 12.2 最低功能矩阵

| 类别 | 必测场景 | 通过证据 |
|---|---|---|
| 初始化/退出 | UI失败、音频/网络线程启动失败、网络暂不可达分别验证；重复启停、SIGTERM、线程阻塞时退出 | UI可降级继续语音；Offline可恢复；致命失败回收；退出有界、无残留自身子进程 |
| 采集格式 | 四通道映射、重采样连续性、256/320余数和元数据延迟 | 样本数/时序断言；真板回采确认 |
| 唤醒/提问 | 唤醒词先通知再监听、点击、短句、句首500ms、长输入上限、静音、无PCM致命错误 | 首帧正确、不漏已准入PCM、正常END只一次；故障不依赖下一帧 |
| 插话 | 候选失败、确认成功、缺参考、低/零音量、恢复音量、旧播完撞上新开始 | 本地停止与新generation的SUPERSEDE都发生，无旧数据串入 |
| 播放 | 长回复、1～480短尾、缺包/补水、EOS与drain；发布取消后暂停实际中断并尝试新起播；停止撞write/drain | 音序连续、尾部完整、取消不误报故障；新起播等旧中断/收尾，终态不覆写 |
| 追问/字幕 | Done与PlaybackDone两种顺序、延迟消费完成、尾Text在窗口内外、纯文本/空回复、旧收尾超时与新首帧同轮 | 观察本轮实际完成后开一次3秒；旧事件不延长/重开；新问题优先使旧超时作废 |
| 网络协议 | 重复/跳序、非法flags、JSON畸形/超长、过时/未来generation、代数耗尽 | 边界明确拒绝；合法旧消息忽略；无wrap、无静默继续 |
| 取消发送 | STOP未发出又来新问题、连续插话、普通PCM背压、控制槽满、首帧准入失败 | START与首PCM整体准入；普通背压取消本轮；控制失败才断连，顺序保留 |
| 队列/慢消费者 | 32帧历史放行叠加已有网络积压、应用卡顿、TTS满、慢网络 | 总PCM缓冲/滞留分别有界、无半个句首批次、断点不伪造END、控制可达 |
| 恢复 | XRUN、设备错误、握手失败、断网、服务重启、连接切换 | 清理作用于正确轮次；恢复后新问答可用，不重播半句 |
| UI | 全页面、触摸坐标、字幕UTF-8、音量预览/保存、重复切页 | 模拟器交互及截图；真板SPI/I²C/音频并行验证 |
| 摄像头 | 短读/半帧、首帧和后续超时、快速退出/重进、管线异常 | 只显示完整新帧、退出无残留、再次进入可恢复 |
| 配网 | 首启二维码、运行中不抢屏、错误凭据、取消/重试、owner竞争、wrapper异常、AP/STA恢复、以太网优先 | 锁与网卡服务交接正确；失败者不清胜者服务；配置保留，网络可用 |
| 构建/ABI | Host、匹配ARM/uClibc、Snowboy旧ABI、ELF和依赖闭包 | 版本对应构建日志，宏只在桥接目标，目标可运行 |
| 更新/回退 | 包损坏、更新中断、启动/配置迁移失败、旧版恢复 | 完整配套一致；UUID/Wi-Fi/SPKI/音量可恢复 |
| 并行负载 | 摄像头预览+字幕+长TTS+插话，持续安静待机 | 无持续XRUN/自激、资源有界、交互不被低优先任务拖死 |

### 12.3 性能与资源

在同一板、同一库/模型/服务版本下比较重构前后：采集每帧处理耗时及最坏值、XRUN、内存峰值/队列容量、线程数、首音延迟、停止时延、追问起点、相机帧率和退出时限。

20 ms 采集节拍是测量基准；不能用平均值掩盖持续超期。未有板端数据前，不编造“性能提升百分比”。初始目标是功能与性能不退化；发现退化先定位新增交接/复制/锁，不让学生加调参开关解决结构问题。

## 13. 与 BSP 衔接的分阶段复现教材

这一轮的代码重构边界是客户端；教材前置部分承接板卡特点、硬件原理图、上电链路、U-Boot、内核/设备树、根文件系统和驱动验证。无需为这次客户端重构改动官方 BSP。

## 14. 风险、差异清单与处理方式

| 风险/待确认点 | 处理方式与关闭证据 |
|---|---|
| 当前脏工作区及远端3提交重叠 | P0完整快照后在隔离分支恢复；逐项正常合入测试变更，保存冲突解决依据 |
| 现有测试锁私有字段/PImpl或源码名字 | 保留业务断言，重写实现绑定；变更测试必须说明保留了哪个行为 |
| 声学逻辑迁线程后节拍变化 | 保持算法常量，测每20ms耗时；新增线程必须有板端数据理由 |
| 放大结果队列增加RAM/滞后 | 按PCM帧核算总容量，测最坏消费者滞后和上行整体时限 |
| 旧停止/完成撞上新播放 | generation标记的一致记录、停止完成与AEC武装握手、确定性调度测试 |
| 尾字幕/Done与追问冲突 | P1补事件表/fixture；独立回复收尾，不延迟播完后的追问 |
| generation耗尽当前路径与协议不一致 | 先复现并登记，再实现重建连接；不静默wrap |
| 短尾重采样可能尚有滤波尾部 | 尾部脉冲与真实短回复检验，不能只凭补零测试判定完整 |
| 子进程组长退出但后代仍在 | 对本程序拥有的管线验证终止及回收；避免shell逃逸或明确约束 |
| 首启配网复用面板后抢屏 | 客户端关闭和运行中两套场景检查唯一设备所有者 |
| 旧配置/新脚本/新ELF混用 | 版本清单、迁移、完整回退演练；配置/身份/凭据不重置 |
| 缺匹配SDK或无法上板 | 继续不依赖硬件的结构工作；ARM/声学/触摸验收明确待办，不虚报 |
| 规则与教材再次固化中间实现 | 标注日期/状态，最终统一当前文档；AGENTS不写临时类名当长期要求 |

P1 建立行为差异台账，记录“现状、原需求、目标、证据、是否改变外部行为”。发现旧实现缺陷可以在自有代码中修正，但必须把修正及验证讲清；不能为了省状态随意删掉协议恢复或设备时序。
